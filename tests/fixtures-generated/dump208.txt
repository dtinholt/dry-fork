456: ### 9.2 Action byte and tables
457: 
458: - L-AC2: the action byte is the 0-based index into the class's pointer list at
459:   `actionClassOffsets[class]` (section 6.2).
460: - L-AC3: in lab tables pointer 0 is always 0x0000. Action byte 0 therefore
461:   means "no record": the class default applies (WALKABLE moves, BLOCKED blocks
462:   silently). Records use slots 1, 2, 3, ...
463: - L-AC4: non-zero pointers ascend and records are stored in pointer order right
464:   after the pointer list, so both the wastelib and the wllib pointer-list rules
465:   (section 6.2) find the same list length.
466: - L-AC5: an action byte at or beyond the pointer-list length, or a null pointer
467:   for a class that needs a record (1, 3, 5, 6, 10), is a data error in lab data.
468: - L-AC6: a class with no records has `actionClassOffsets[class] = 0`.
469: 
470: ### 9.3 Tail
471: 
472: - L-TL1: `newActionClass` 0 to 15 replaces the cell's class and action byte with
473:   `(newActionClass, newAction)` after the action has fired once; 255 changes
474:   nothing; lab encoders never write 16 to 254. The engine treats 16 to 254 in
475:   lab data as 255 and logs a warning.
476: - L-TL2: replacements are part of the game state and are saved with it; the
477:   base map files are never modified.
478: 
479: ### 9.4 SHOP record (class 6, lab layout)
480: 
481: ```text
482: u8 shop list number (SPEC-02 rule L-SH3)
483: u8 message index
484: tail (8.3)
485: ```
486: 
487: ### 9.5 Messages and monsters
488: 
489: - L-MS1: a message index `m` selects map string `m` (0-based, group x 4 +
490:   slot). Lab maps keep string 0 empty, so `m = 0` shows nothing.
491: - L-MS2: messages are shown in order; a 0x06 control byte waits for a key.
492:   PRINT records may hold the text "Read paragraph N."; the paragraph book is a
493:   separate lab document, outside these formats. This is the lab's paragraph
494:   trigger.
495: - L-MB1: in encounter records, monster index 0 = empty slot, `n >= 1` = map
496:   monster `n - 1`.
497: - L-MB2: group size: if the random flag is set, `rnd(size)` with `rnd` from
498:   section 6.6; otherwise exactly `size`; if `size` is 0 in a used slot, use the
499:   monster's own maximum group size nibble.
500: - L-MB3: lab encoders write the encounter NPC number and bit 3 of the flag
501:   byte as 0. Visible distance, hit distance, proper name and immobile are
502:   written as data; the lab v1 engine exposes them and ignores them.
503: 
504: ### 9.6 Movement and triggers
505: 
506: The party occupies one cell. A move targets the adjacent cell `(nx, ny)`.
507: 
508: 1. Out of bounds (`nx` or `ny` outside 0 to S-1): blocked, no message (L-MV1).
509: 2. Look up the target cell's class `c` and action byte `a`, and record `r`
510:    (null if `a = 0`).
511: 3. Act by class:

=== SPEC/SPEC-03-maps.md :: 9.9 Encoder rules for lab map blocks (line 574) ===
574: ### 9.9 Encoder rules for lab map blocks
575: 
576: - L-EN1: body order: action-class map, action map, central directory, map info,
577:   action tables 0 to 7, table 15, NPC section, tables 8 to 14, specials,
578:   monster names, monster data, strings (the wllib order of section 6.1).
579: - L-EN2: the encrypted prefix is exactly `body[0 : stringsOffset]`; strings and
580:   anything after them are plain. The prefix must pass the ambiguity check of
581:   SPEC-01 section 2.7. The fixture generator nudges monster sturdiness until it
582:   passes.
583: - L-EN3: `specialsOffset = 0` (no special-action table).
584: - L-EN4: a map with no NPCs sets `npcOffset = stringsOffset`. The u16 there
585:   (`20 65`, read as 0x6520) is non-zero, so the `map.md` rule reads "no NPCs",
586:   and wllib sees a zero-length section because strings outrank the NPC table.
587: - L-EN5: string dictionaries start with `20 65` (SPEC-02 L-ST3), so wllib's
588:   `20 65` guard accepts the same prefix end as the wastelib rule.
589: - L-EN6: strings fill the body to its end, with no padding; string 0 is empty
590:   (L-MS1); groups hold exactly 4 strings (SPEC-02 L-ST1).
591: - L-EN7: the unknown byte before the tile-map section and the unknown u32 after
592:   `tileMapDecodedSize` are 0.
593: - L-EN8: no map block contains the bytes `msq` after its 4-byte header (keeps
594:   wllib's scanning reader working; the generator checks and fails otherwise).
595: - L-EN9: every map has at least one monster, so `mobNamesOffset <
596:   mobDataOffset < stringsOffset`.
597: 
598: ### 9.10 Replacing lab rules with parity
599: 
600: A parity loader keeps sections 3 to 8 and the decoders unchanged and swaps in:
601: the WL.EXE table source (SPEC-02 section 3.3) for LABTABLES.BIN; the real
602: semantics of classes 1 to 15 for 9.1 to 9.7; real map-info units for L-MI2 to
603: L-MI4. Every lab rule is named (L-xx) so the parity milestone can list which
604: ones it overrides.

606: ## 10. Disagreements between wastelib and wllib (maps)
607: 
608: | Topic | wastelib | wllib | Engine rule |
609: | --- | --- | --- | --- |
610: | Action-class nibble order | high nibble = even x (`map.md`, `GameMap.ts`) | low nibble = even x (`decode/mapdata.go`) | wastelib; wllib's `EncodeMapData` also steps x by 1 inside a 2-cell loop and would overrun its buffer, so its writer is not a reliable witness |
611: | Map info +0x0A, +0x0B | u16 time per step | u8 seconds rate, u8 minutes rate | read u16, expose both bytes; lab rule L-MI2 |
612: | Map info +0x0D | u8[37] combat string ids | u16[18] string ids + 1 padding byte | read 37 raw bytes |
613: | Map info +0x00, +0x01, +0x03, +0x04 | unknown | padding | UNKNOWN |
614: | End of encrypted prefix | first checksum match | match plus raw `20 65` next | wastelib; lab data satisfies both |
615: | No-NPC marker | first u16 at npcOffset non-zero | npcOffset 0 or shared with a higher-priority section | read with the `map.md` rule; lab data satisfies both |
616: | Class 6 | SPECIAL | "shop" (`IDShop`) and "special actions" | UNKNOWN for parity; lab SHOP |
617: | Transition X and Y | signed bytes | unsigned bytes | lab: unsigned when absolute, signed when relative (L-TR3) |
618: | Pointer-list length | until the smallest non-zero pointer | from the first non-zero pointer | lab data keeps pointers ascending so both agree |
619: | Last string group pointer | used if inside the data | "garbage", dropped | do not fail on it |
620: | Tile map | Huffman decoded | not decoded (opaque) | wastelib |

622: ## 11. Validation checklist
623: 
624: For every map (`map.md` validation notes plus the rules above):
625: 
626: 1. Header `msq0` or `msq1` matches the file.
627: 2. Prefix decryption finds a checksum match inside the body.
628: 3. `tileMapDecodedSize == S x S`; map info +0x02 equals the table size.
629: 4. Every non-zero central-directory offset is inside the body.
630: 5. `prefixLength == stringsOffset` (warning for parity data, error for lab
631:    data).
632: 6. `(stringsOffset - mobDataOffset)` is a multiple of 8.
633: 7. NPC pointers point at 0x100-byte records inside the body.
634: 8. Action pointer lists end inside the body and every record parses inside the
635:    body.
636: 9. Lab data only: rules L-AC1 to L-AC6, L-EN1 to L-EN9.
